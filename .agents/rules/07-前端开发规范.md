# 前端开发规范

## 技术与目录

- 使用 Vue 3 Composition API、`<script setup lang="ts">` 和严格 TypeScript，不使用 `any` 隐藏接口问题。
- `views/` 存放路由页面，`layouts/` 存放应用布局，`components/` 存放可复用界面，`api/` 存放请求与接口适配，`styles/` 存放基础样式。
- 根据实际职责建文件，不预建空业务模块；出现真实跨页面状态后再引入状态管理。
- 统一使用 Node 24 和 package.json 声明的 pnpm 版本，提交 pnpm-lock.yaml，不混入其他包管理器锁文件。

## 接口与状态

- 通过 `api/client.ts` 处理 JSON 请求；接口适配层校验未知响应，不直接把网络数据强转成可信业务对象。
- 展示加载、成功、失败和重试；失败不伪装成空数据或成功。
- 保留后端 requestId 供定位错误，不在页面展示代理 HTML、堆栈或原始网络异常。
- 页面卸载时取消未完成请求，处理超时，不让旧请求覆盖新结果。
- 不在页面中模拟未完成业务或将规划功能标为已可用。测试中的模拟响应必须有清晰边界。

## 安全与可访问性

- 密钥和密码不写入前端源码、VITE_ 变量或提交文件；浏览器中的配置视为公开信息。
- 不使用 v-html 渲染接口返回的任意内容，不输出令牌、文档正文或个人数据到控制台。
- 导航使用 RouterLink 或链接，操作使用 button；表单设置标签，图标按钮提供可访问名称。
- 提供键盘焦点、状态提示、移动端布局；纯装饰图使用空 alt 或 aria-hidden。
- 权限由后端强制校验，前端路由守卫只改善体验。

## 验证

- 前端改动运行 pnpm lint、pnpm typecheck、pnpm test、pnpm build。
- 请求边界、超时和错误契约需要测试；不要为静态文案和简单样式机械编写测试。
- 影响页面行为时在真实浏览器验证网络响应、控制台、错误恢复、直接刷新和移动端布局。
- Vite 开发代理仅用于开发；生产同域反向代理和 history 路由回退需在部署阶段单独配置验证。
