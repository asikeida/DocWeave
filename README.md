# DocWeave

DocWeave 是兼顾个人使用与企业内部知识协作的智能文档知识库。个人可在独立区域管理资料，企业成员可在授权范围内查询公司制度、部门知识和项目资料，并在问答中保留可回溯的引用证据。

项目将作为可在线访问的求职作品持续迭代。当前开发分支已实现登录、受控开发注册及个人区域初始化；个人知识库与两份示例入库已实现；企业管理、文件上传和问答仍在后续计划中。注册默认关闭，尚未开放公网试用。

## 当前技术基线

- Java 21
- Spring Boot 4.1.1
- Maven Wrapper
- Spring Data JPA
- MySQL
- Flyway
- Bean Validation
- Spring Boot Actuator
- OpenAPI / Swagger UI

前端采用 Vue 3、TypeScript 和 Vite，位于 `frontend/` 目录，目前提供概览、404、健康检查、登录、注册、账号和个人区域页。认证采用 Spring Security、JWT 及可撤销登录记录。前后端独立构建与部署，但由同一个 Git 仓库管理。

## 计划功能

1. 个人与企业组织、账号、成员、部门和工作空间授权
2. 知识库与文档管理
3. 文档解析、切分和异步处理
4. 检索、索引和权限过滤
5. 基于引用证据的智能问答
6. 对话历史、引用预览和在线演示

完整路线见 [项目骨架与模块开发路线](docs/开发规划/01-项目骨架与模块开发路线.md)。
个人与企业方案作为已合并设计基线，见 [企业场景与权限模型](docs/架构设计/01-企业场景与权限模型.md)、[RAG 授权与撤权设计](docs/架构设计/02-RAG授权与撤权设计.md) 和 [M1 实施计划](docs/开发规划/03-M1账号与工作空间实施计划.md)；目前只实现账号登录，不代表这些企业与 RAG 业务均已完成。
规划提供独立个人试用与只读企业演示两条入口，个人资料、企业资料及各自会话相互隔离；当前尚未开放这些体验功能。
接口约定见 [接口设计约定](docs/接口说明/01-接口设计约定.md)。日志配置与查询见 [日志与请求追踪](docs/部署运维/02-日志与请求追踪.md)。

## 文档规则

- 长期有效的设计、接口、部署和决策文档放在 `docs/` 并提交。
- 临时分析、调试记录和未整理的 AI 草稿放在 `.local/`，不会提交。
- 不在仓库中保存密码、令牌、私钥、生产服务器地址或其他敏感信息。

## 开发方式

自动构建流程见 [后端自动构建与测试](docs/部署运维/03-后端自动构建与测试.md)（运行结果以 GitHub Actions 为准）。

- 每个任务从最新 `main` 创建短期分支。
- 每个提交只处理一个清晰目标。
- 合并到 `main` 前应通过与改动匹配的测试和构建验证。
- 详细协作规则见 [AGENTS.md](AGENTS.md)。

提交信息、PR 关联与 main 保护见 [提交规范与质量门禁](docs/部署运维/08-提交规范与质量门禁.md)。根目录 Node 工具仅用于协作校验，与 frontend 的依赖独立。
个人初始化开发分支已增加注册与个人区域后端及最小页面，注册默认关闭。配置与边界见 [注册与个人区域接口](docs/接口说明/03-注册与个人区域接口.md)。示例已支持独立入库，问答未实现。

当前提供两份虚构模板的只读原文和推荐问题，见 [个人示例只读预览](docs/接口说明/04-个人示例只读预览.md)；模板仍未索引，不能问答。

个人知识库开发分支支持两份示例的独立入库、文档列表与正文快照，均未索引、不能问答。见 [个人知识库与示例入库](docs/接口说明/05-个人知识库与示例入库.md)。

首版容器、HTTPS、备份及验收步骤见 [生产部署与验收](docs/部署运维/09-首版生产部署与验收.md)。
