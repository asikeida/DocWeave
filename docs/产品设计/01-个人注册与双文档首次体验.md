# 个人注册与双文档首次体验

> Issue #15，2026-11-01，设计阶段。本稿保留总体设计。当前实现了注册与个人区域的最小闭环，实际范围以[注册与个人区域接口](../接口说明/03-注册与个人区域接口.md)为准；Issue #17 已实现个人示例入库与有界消费任务，检索与问答未实现；最新契约见[个人知识库与示例入库](../接口说明/05-个人知识库与示例入库.md)。分支基于登录提交797cc64，按用户要求暂不合并main。设计记录不代表已开放试用。

## 1. 用户首次进入

注册成功后进入“我的资料”，显示示例知识库和两份虚构文档；可点击推荐问题、查看引用、上传自己的文件。此为最终体验目标。注册与个人空间先实现，知识库/解析/检索/问答按M2～M5接入；此前显示“示例资料待接入”，不显示可以发送问题的按钮。

示例原文在本目录“示例资料/v1/”。当前只是可版本管理的产品素材，不放resources伪装为已接入运行时种子。实现示例初始化时再随实际加载器纳入运行产物。

## 2. 注册与个人空间的事务

注册请求只接受username、password、displayName。沿用既有账号规范与BCrypt策略，不接受tenantId、role、ownerId等权限字段。使用同一数据库事务依次写账号、PERSONAL组织、唯一ACTIVE OWNER成员、默认“我的资料”空间、本人直接ADMIN授权、初始化待办与审计事件；任意数据库写入失败全部回滚。

注册不自动加入任何企业，不授予平台管理员，不直接自动登录。提交成功返回201及最小账号/个人区域ID，客户端再走既有登录接口；登录失败不撤销已注册账号，可重新登录。超时后重新注册由用户名唯一约束拦截，提示回到登录，不创建第二个个人组织。

数据库约束设计：users已有用户名唯一；organizations的personal_owner_user_id唯一且PERSONAL必填；个人成员必须等于个人组织所有者，以复合外键或等效约束落实；memberships唯一(tenant_id,user_id)；workspaces携带tenant_id；direct_grants复合引用同组织成员和空间，唯一(tenant_id,workspace_id,membership_id)；个人区域bootstrap记录按user_id唯一。企业相关取值以后通过新增迁移扩展，不在本阶段创建邀请/部门表。

已有受控开发账号首次进入时，由受保护的POST /api/v1/personal-area/initialize执行幂等补建，锁定user行并复查bootstrap。补建不会重置密码、修改现有资源或恢复用户已删除的示例。GET不得偷偷创建资源。并发重复请求得到相同区域，不能因为一次唯一冲突把部分数据留在库中。

注册入口默认关闭，local/test显式启用；生产在反滥用与部署验收完成前保持关闭。首批限制候选为单来源每小时5次、单实例同时创建总量有界、账号名3～64字符、密码12字符且UTF-8不超过72字节。准确阈值实现时配置化并测试；不信任任意X-Forwarded-For；多实例共享限流留待明确部署方案。

## 3. 默认内容权限

账号是全局身份；PERSONAL组织只允许这个账号成为成员，不接受邀请、部门或所有者转移。空间ADMIN由真实授权记录产生，不靠“创建者直接放行”。所有资源读取核验组织ACTIVE、成员ACTIVE及空间授权，客户端传的tenantId只是选择，不是权限证明。

GET /api/v1/personal-area返回当前账号的组织/空间及示例准备状态。GET /api/v1/workspaces/{id}只能返回当前有效组织内有权进入的空间；跨组织猜ID统一404。受保护请求沿用JWT和数据库实时会话核验。后续Cookie驱动写接口需一并扩展CSRF范围，不能只靠现有auth路径规则。

## 4. 示例初始化与恢复

注册事务只创建可靠待办，不在事务中下载、解析、调用模型或写索引。待办记录与个人区域一起提交，避免“注册成功、任务丢失”。M1先将状态置WAITING_FEATURE；只有知识库文档模块可用时才消费。M1不引入Kafka或临时线程模拟可靠任务。

后续消费者建立用户自己的示例知识库与两份文档业务记录；静态示例字节可以复用只读源文件，但删除、版本、权限和聊天都按个人组织隔离，不能共用一条可修改业务文档记录。幂等键(tenant_id,seed_version,sample_key)，文档内容带固定校验和。模板升为v2不自动覆盖已存在用户资料。

状态：WAITING_FEATURE → PENDING → PROCESSING → READY；失败为FAILED，可重试。只有两份资料的实际索引就绪才READY。租约/重试次数/错误摘要需可恢复，失败不回滚账号，用户仍可登录。错误摘要不含敏感正文。

用户删除文档后记录删除状态，刷新页面、重新登录、服务重启不能自动补回。显式“恢复示例资料”需用户确认，仅恢复本版本缺失或已删除的示例，不覆盖用户上传内容、不同名同内容文件或已编辑资料；一次恢复请求生成新处理代次，旧任务不能复活旧资源。知识库和文档接口尚未实现，此处只是约束。

## 5. 推荐问题及答案依据

| 问题 | 应答事实 | 引用 |
| --- | --- | --- |
| 试用期员工能申请远程办公吗？ | 可以，提前一个工作日申请，经直属负责人批准 | 员工手册“远程办公” |
| 住宿每晚600元可以全额报销吗？ | 常规上限450元，超限需事先批准例外，不能直接承诺全额 | 报销指南“交通与住宿” |
| 出差三天，出发前和回来后需要做什么？ | 提前两个工作日审批、填写目的地日期目的预算；结束后十个工作日内提供审批号明细发票支付凭证等 | 两份文档对应章节 |
| 出差回来餐补每天多少？ | 当前资料未规定，提示咨询财务 | 报销指南“资料边界” |

READY之前的问题卡仅作功能预告，不能伪造AI答案。真正问答验收必须从召回证据产生引用，不能用硬编码答案冒充RAG。未来回答和会话只属于本人；模板来源不形成跨用户聊天共享。

## 6. 待实现接口契约

## 7. 验收矩阵与实施顺序

第一实现阶段：追加V2，组织/成员/空间最小实体和Repository，注册与幂等补建Service，Controller与Security边界；测试注册完整性、任一步故障全部回滚、并发注册/补建、密码不泄漏、无全局角色、两账号ID猜测、停用和错误响应。真实MySQL测试必须用新隔离库，不把测试指向共享开发库。既有MySQL测试中只适用于V1的数量断言要改为当前迁移版本断言，不能破坏V1内容。

第二阶段：注册和个人区域最小页面，加载/失败/重试，明确待接入状态；浏览器核验并同步真实API到Apifox。

示例导入、删除、恢复及问答在M2～M5逐步接入，每阶段独立验收。必须测试幂等重试、READY前不可问答、旧任务代次、删除后不自动恢复、跨账号隔离、资料外问题拒绝编造及双文档引用。
