# 提交规范与强制质量门禁

关联 Issue #14。本轮从 main 独立开发，登录功能保留在 feat/auth-login-账号登录 的本地提交 797cc64，尚未合并。

## 本机使用

根目录的 package.json 只管理仓库质量工具，与 frontend/package.json 独立；不改变 Maven 构建或前端依赖。使用 Node 24 和 pnpm 11.25.0：

```text
pnpm install --frozen-lockfile --ignore-scripts
pnpm hooks:install
pnpm test
```

安装钩子只修改本仓库 core.hooksPath，不修改全局 Git。新克隆的同伴需要执行一次；IDEA 必须能在启动时的 PATH 找到 Node 24。Git hook 是 Git for Windows/Linux/macOS 通用的 sh 入口，直接调用 Node，不依赖 PS1 或全局 commitlint。

提交格式：

```text
feat(auth): 新增密码登录接口

Refs: #13
```

允许 feat/fix/docs/style/refactor/perf/test/build/ci/chore/revert/infra；范围可选，只能是小写英文模块名。摘要必须有中文，沿用 Conventional Commits 其他格式约束；中文内容是否准确仍需人工审核。Refs 放在独立正文行；多个关联写 Refs: #13, #14。合并提交和 fixup 不设默认跳过，最终提交前应整理好。

本地钩子检查格式，不联网验证编号；远端检查会确认编号存在且不是 PR。旧 main 提交不重新检查。

## PR 与远端校验

标题使用同样格式但不强制 Refs；正文独立一行 Closes #14，多个写 Closes #14, #15。不要把这些关联只写在代码块或 HTML 注释中。PR 编号由 GitHub squash 时附加；它和 Issue 编号是两回事。

Collaboration CI 监听打开、更新提交、重开、编辑标题/正文及转为可审核的 PR，检查 PR 当前标题、正文、所有新增提交与真实 Issue。允许引用已关闭 Issue（后续修复也可能引用），但不接受 PR 代替 Issue。只支持本仓库的 #数字，跨仓库关联不是本轮范围。最多 250 个提交，超限提示拆分，避免 GitHub 分页截断后漏检。

只读 GitHub Token 仅用于官方 API；正文不会插入 shell 执行，不使用 pull_request_target。网络错误、权限错误或资源不存在时检查失败，不默默放行。检查结束会再核对 PR 是否变化；后续每次编辑重新触发。检查是当时状态的快照，不是对之后所有修改的永久证明。

本地钩子可以绕过；工作流和规则本身也能被有权限的开发者在 PR 中改动，因此仍需人工审核治理文件。本轮没有企业级独立规则仓库或不可修改的组织工作流。

## 已启用与待启用

Collaboration verify 这项新检查目前只在本地代码中，尚未推送或实际远端运行，暂未加入 required checks。待本分支经审核、推送创建 PR 且新工作流成功后，再将该名称加入必需项；不能提前宣称提交信息已被远端强制拦截。

GitHub 设置不随本地文件或 Git 提交回滚。要撤回保护需仓库管理员明确操作；不要为一次失败测试随意关闭门禁。尚未在远端制造违规 PR，不能将 API 回读设置等同于失败合并的端到端验证。
