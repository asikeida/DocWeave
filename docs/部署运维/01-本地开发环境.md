# 本地开发环境

日常开发使用 [云端开发数据库](06-云端开发数据库与DBeaver.md)，本机代码通过 SSH 隧道连接，无需启动本机 Docker。以下本机 MySQL Compose 流程保留为可选方案。

后端使用 Java 21、Maven Wrapper 和 MySQL 8.4。Docker Compose 运行数据库，应用通过 IDE 或 Maven Wrapper 启动，支持 Windows、Linux 和 macOS。前端另见 [前端开发与连通验证](04-前端开发与连通验证.md)。

## 1. 准备配置

首次运行时在项目根目录创建配置；已有 `.env` 时保留原文件：

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

修改本地数据库密码，并按需调整端口。示例中的 replace-with 值是占位符，不是建议使用的密码。`.env` 被 Git 忽略，不能提交或打印。

Docker Compose 会自动读取根目录 `.env`。Spring Boot 本身不会自动读取；应用配置由终端环境变量或 IDE 运行配置提供，值应与 `.env` 一致。项目不依赖专用启动脚本。

Linux / macOS 首次复制配置：

```bash
[ -f .env ] || cp .env.example .env
```

## 2. 启动 MySQL

确认 Docker Desktop 已启动：

```powershell
docker info
docker compose config --quiet
docker compose up -d --wait --wait-timeout 180
docker compose ps
```

MySQL 仅绑定本机 `127.0.0.1`，默认宿主机端口为 3306。如果本机已有 MySQL，在 `.env` 中选择空闲的 `DOCWEAVE_DB_PORT`，例如 13306。容器内部端口保持 3306。

健康检查使用应用账号登录目标数据库并执行 `SELECT 1`，确认的不只是 MySQL 进程存在。

数据库使用项目的 named volume `mysql-data` 持久化。停止容器可执行：

```powershell
docker compose down
```

该命令保留数据卷。不要为排查启动问题随意添加 `-v`：它会删除数据库数据。已有数据卷的账号密码不会因为修改 `.env` 就自动变更；此时应检查原凭据或按 MySQL 的账号管理方式修改。

## 3. 启动后端

### Windows（PowerShell）

确认 `JAVA_HOME` 指向 JDK 21。在项目根目录设置当前终端的环境变量，值与 `.env` 保持一致：

```powershell
$env:DOCWEAVE_DB_HOST = '127.0.0.1'
$env:DOCWEAVE_DB_PORT = '13306'
$env:DOCWEAVE_DB_NAME = 'docweave'
$env:DOCWEAVE_DB_USERNAME = 'docweave'
$env:DOCWEAVE_DB_PASSWORD = '<本地数据库密码>'
.\mvnw.cmd spring-boot:run
```

13306 是宿主机端口示例，按实际 `.env` 修改；密码占位值需自行替换。根密码仅供 Compose 使用，不传给应用。

### Linux / macOS（Bash / Zsh）

确认 `JAVA_HOME` 指向 JDK 21，在项目根目录设置相同环境变量：

```bash
export DOCWEAVE_DB_HOST='127.0.0.1'
export DOCWEAVE_DB_PORT='13306'
export DOCWEAVE_DB_NAME='docweave'
export DOCWEAVE_DB_USERNAME='docweave'
export DOCWEAVE_DB_PASSWORD='<本地数据库密码>'
bash ./mvnw spring-boot:run
```

使用 `bash ./mvnw` 不要求文件具有可执行权限。mvnw.cmd 和 mvnw 都是项目已有的标准 Maven Wrapper 入口，不另维护平台专用启动逻辑。不要直接执行或 source `.env`，其中的值可能包含 shell 特殊字符。

两种方式默认使用 local profile、应用端口 8080。可在当前终端设置 `SERVER_PORT=18081` 改用其他端口；设置 `SERVER_ADDRESS=127.0.0.1` 可限制为仅本机访问。这些环境变量只影响当前终端及其子进程，不修改系统全局配置。真实密码不能写进可提交文件。

### IntelliJ IDEA

选择 JDK 21，在运行配置设置以下环境变量，值与 `.env` 一致：

```text
DOCWEAVE_DB_NAME=docweave
DOCWEAVE_DB_USERNAME=docweave
DOCWEAVE_DB_PASSWORD=<本地数据库密码>
DOCWEAVE_DB_HOST=127.0.0.1
DOCWEAVE_DB_PORT=<.env 中的宿主机端口>
```

然后运行 `DocWeaveApplication`。默认 profile 为 local。IDE 运行配置同样需要传入环境变量，不能假定会自动读取根目录 `.env`。

## 4. 验证运行状态

以默认应用端口为例：

```powershell
Invoke-RestMethod http://127.0.0.1:8080/actuator/health
```

预期 status 为 UP；如果使用了其他应用端口，相应替换 URL。

浏览器打开：

- `http://127.0.0.1:8080/swagger-ui.html`：接口调试页面。
- `http://127.0.0.1:8080/v3/api-docs`：OpenAPI 定义。

同时检查启动日志中的 Flyway 执行信息和本地 `.local/logs/docweave.log`。API 错误响应返回 X-Request-Id，可用于关联请求日志。

前端开发代理默认连接 8080；若后端改用 18081，需要按前端文档调整 DEV_PROXY_TARGET。

## 5. 测试与数据库迁移

确认使用 JDK 21 后执行：

```powershell
./mvnw.cmd --batch-mode --no-transfer-progress verify
```

Linux / macOS 对应运行：

```bash
bash ./mvnw --batch-mode --no-transfer-progress verify
```

自动测试使用 test profile 和 H2，不需要 Docker。Flyway starter 提供 Spring Boot 4 的自动配置，flyway-mysql 提供真实 MySQL 支持；只添加 flyway-core 不足以证明自动迁移已经接入。

当前尚无业务表。正常启动会建立 Flyway 历史表，但没有生产 V1 迁移；JPA 使用 validate，只校验已有结构，不建表或改表。

首个需要持久化的业务模块提交时，在 `src/main/resources/db/migration/` 新增 `V1__<英文说明>.sql`，与实体和 Repository 一起验证。`src/test/resources/db/verification/` 的 V1 是独立验证夹具，只在明确指定位置的测试或隔离数据库验收中使用，不打入生产 JAR，不是业务数据库版本历史。

H2 的迁移测试不能替代 MySQL 专属语法和实际业务迁移的验证。新增业务表后继续补充真实 MySQL 集成测试。

参考：[Spring Boot 数据库初始化](https://docs.spring.io/spring-boot/how-to/data-initialization.html)。
