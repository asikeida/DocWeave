# 后端自动构建与测试

## 当前状态

工作流已配置，首次远端运行通过 Pull Request 验证。实际状态以 GitHub Actions 和 PR 检查结果为准；本地构建成功不能替代远端 CI 结果。

对应文件为 `.github/workflows/backend-ci.yml`，对应 Issue 为 #5。

## 执行时机

- 创建或更新目标分支为 `main` 的 Pull Request。
- 推送或合并提交到 `main`。
- 工作流进入默认分支后，在 Actions 页面手动运行。

不限制文件路径，因此仅修改文档的 PR 也会触发检查。同一个 PR 或分支再次触发时，取消仍在执行的旧运行，优先验证最新改动。

## 每一步做什么

| 步骤 | 作用 |
| --- | --- |
| Checkout repository | 获取本次需要验证的代码；不在工作目录保留 Git 凭据 |
| Set up Java 21 and Maven cache | 配置 Temurin JDK 21，缓存 Maven 依赖，按构建配置生成缓存键 |
| Run tests and build JAR | 使用项目 Maven Wrapper 执行 `verify`：编译、测试、打包及已配置的校验 |
| Upload test reports on failure | 构建失败且已生成测试报告时上传 XML / 文本报告，保留 7 天；未生成报告时给出警告 |

运行环境为 GitHub 托管的 Ubuntu 24.04，单个任务最多执行 20 分钟。第三方 Action 固定到已核对的完整提交 SHA，行末注释标记对应版本，升级时需同时更新两者。

`mvnw` 在仓库中当前没有可执行权限位，因此 Linux 使用 `bash ./mvnw`，避免依赖本机文件权限。Wrapper 根据 `.mvn/wrapper/maven-wrapper.properties` 使用 Maven 3.10.0。

## 数据与权限

任务使用 `SPRING_PROFILES_ACTIVE=test`，测试加载 `src/test/resources/application-test.yaml` 的 H2 内存数据库。不启动 Compose，不连接本地 MySQL 或生产服务器，不需要在 GitHub 设置数据库密码或部署密钥。

工作流只申请 `contents: read`，用于检出代码。使用普通 `pull_request` 事件，不使用有额外权限风险的 `pull_request_target`。

H2 测试不能证明 MySQL 特有 SQL 或数据库迁移在真实 MySQL 上可用；后续接入持久化模块时补充对应集成测试。

## 如何查看结果

推送后打开仓库 **Actions → Backend CI**，选择一次运行，展开失败的步骤查看日志。PR 页面也会显示 `Backend verify (Java 21)` 检查结果。

若测试失败，进入该次运行的 Artifacts 下载 `backend-test-reports-<run-id>-<attempt>`。编译失败或依赖下载失败时可能没有测试报告，此时以构建步骤日志为准。取消或超时不保证能够上传报告。

测试报告可能包含异常消息和测试输出；测试应只使用合成数据，不能引用真实用户数据或密钥。

## 本地复现

使用 JDK 21，在项目根目录运行：

```powershell
$env:SPRING_PROFILES_ACTIVE = 'test'
.\mvnw.cmd --batch-mode --no-transfer-progress -Dstyle.color=never verify
```

Linux / macOS：

```bash
SPRING_PROFILES_ACTIVE=test bash ./mvnw --batch-mode --no-transfer-progress -Dstyle.color=never verify
```

`test` 是 Spring 配置环境，不能用 Maven 的 `-Ptest` 替代。`verify` 成功会生成 `target/docweave-0.0.1-SNAPSHOT.jar`；当前工作流不上传或发布该 JAR，也不部署服务器。

## 本次本地验证

- 生成 Spring Boot 可执行 JAR；没有启动或部署该 JAR。
- 使用 actionlint 1.7.12 检查工作流语法和表达式，通过。校验器临时保存在被 Git 忽略的 `.local/`，未安装到系统目录。
- 本机验证不能覆盖 GitHub Linux runner、缓存恢复和报告上传；这些待推送后验证。

## 后续验收

首次授权推送后，需要确认 GitHub 实际运行通过、11 项现有测试成功且 JAR 构建完成。失败报告上传条件已配置，远端上传行为仍需在受控失败运行中验证。

工作流通过不等同于强制合并门禁。是否将该检查设为分支保护的必需项，需要工作流稳定运行后另行确认。
