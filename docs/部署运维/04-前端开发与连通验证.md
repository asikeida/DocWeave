# 前端开发与前后端连通验证

## 当前范围

前端位于 `frontend/`，使用 Vue 3、TypeScript、Vue Router 4 和 Vite。当前提供项目概览、应用布局、404 路由及真实后端健康检查；知识库、上传、问答和登录属于后续业务模块。

界面中“规划中”的内容只用于说明项目方向，不提供模拟业务数据。连接状态来自实际请求，不由前端固定为成功。

## 运行要求

- Node.js 24，pnpm 使用 `frontend/package.json` 的 packageManager 指定版本（当前 11.25.0）。
- 使用已安装的 pnpm；不要在任务中随意修改全局 Node 或包管理器配置。
- 后端正常开发启动方式见 [本地开发环境](01-本地开发环境.md)。默认监听 8080。

首次进入前端目录安装依赖：

```powershell
Set-Location frontend
pnpm install --frozen-lockfile
pnpm dev
```

打开 `http://127.0.0.1:5173`。端口已被占用时 Vite 会报错，不会自动换端口。

## 开发代理与配置

浏览器访问同域相对路径，Vite 开发服务器将 `/api` 与必要的 `/actuator/health` 请求转发至后端。业务接口的 `/api/v1` 前缀保持原样，不做移除前缀的重写。不代理其他 Actuator 端点。

默认后端为 `http://127.0.0.1:8080`。若后端端口不同，在 `frontend/` 中复制示例配置：

```powershell
Copy-Item .env.example .env.local
```

再修改：

```dotenv
DEV_PROXY_TARGET=http://127.0.0.1:8080
```

`.env.local` 被忽略，修改后重启前端开发服务器。也可以只在当前 PowerShell 进程设置 `$env:DEV_PROXY_TARGET` 后启动，避免创建本机配置文件。

`DEV_PROXY_TARGET` 只供 Vite 服务器配置使用。以 `VITE_` 开头的变量可进入浏览器产物，禁止放置密码、访问令牌或其他秘密。根目录的 Compose `.env` 不会代替前端目录的配置。

| 文件 | 职责 |
| --- | --- |
| `package.json` | 声明工具版本、依赖和开发命令 |
| `pnpm-lock.yaml` | 锁定依赖解析结果，供本地与 CI 重复安装 |
| `index.html`、`src/main.ts` | HTML 容器与 Vue 启动入口 |
| `src/App.vue` | 根路由视图 |

| `src/layouts/AppLayout.vue` | 导航、顶栏、主内容及页脚 |
| `src/views/` | 首页与找不到页面时的界面 |
| `src/components/ServiceStatus.vue` | 健康状态、加载、错误提示和重试；离开页面时取消请求 |
| `src/api/client.ts` | JSON 请求、10 秒超时、HTTP 错误与 requestId 处理 |
| `src/api/health.ts` | 健康检查接口适配，仅在返回 UP 时视为就绪 |
| `src/api/*.test.ts` | 验证请求错误、超时、取消和健康响应契约 |
| `src/styles/main.css` | 颜色、布局、键盘焦点和移动端样式 |
| `public/favicon.svg` | 项目标识，不含外部图片依赖 |
| `vite.config.ts` | Vue 编译、开发代理、固定端口和测试运行配置 |
| `tsconfig.json` | 严格 TypeScript 检查 |
| `eslint.config.js` | Vue 与 TypeScript 静态检查规则 |
| `.env.example` | 可提交的开发代理示例 |

代码优先使用浏览器内置 fetch，不额外引入 HTTP 库。没有实际跨页面共享状态，暂不引入 Pinia。TypeScript 保持 5.9 系列，以匹配当前 ESLint TypeScript 插件声明的兼容范围，不盲目采用不兼容的最新主版本。

## 请求失败时会发生什么

- HTTP 错误：保留后端的错误码、消息和 requestId；优先读取 X-Request-Id 响应头。
- 代理 HTML 错误或连接故障：显示通用提示，不输出原始 HTML 或网络堆栈。
- 超过 10 秒：终止请求并提示重试。
- 离开页面：取消当前请求，避免过期结果覆盖新页面状态。
- 缺少有效健康状态：不显示“连接正常”。

`requestJson` 用于有 JSON 响应的接口，不适用于 204 空响应、文件下载或流式问答；这些需求出现时设计独立处理方式。

## 质量命令与 CI

在 `frontend/` 执行：

```powershell
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

`build` 生成 `frontend/dist/`，构建产物和 node_modules 不提交。类型检查单独执行，因为 Vite 的生产构建不代替完整的 TypeScript 检查。

`.github/workflows/frontend-ci.yml` 在指向 main 的 PR、main 推送及手动触发时，使用 Node 24 和 packageManager 指定的 pnpm，依次执行锁文件安装、lint、类型检查、契约测试及生产构建。该工作流使用只读仓库权限，并取消同一 PR 的旧运行。

前端 CI 的远端结果以本次 PR 的 GitHub Actions 检查为准；本地验证不能替代远端运行。后端 CI 独立保留。

## 浏览器与部署边界

本阶段需检查：真实健康请求、失败后重试、404、浏览器刷新、窄屏布局和控制台错误。受控失败测试中的模拟响应只用于故障验证，不作为实际后端连通证据。

本机 Docker 未启动，因此本阶段连通验证使用独立 H2 测试运行时后端，不能据此宣称真实 MySQL 或 Flyway 验收完成。

`pnpm preview` 只预览静态产物，不提供开发代理，也不是生产服务器。生产部署时需要另行配置 Nginx：静态资源、SPA history 路由回退、`/api` 反向代理，以及按需开放的健康端点。当前不部署应用。

## 本次验证结果

- Node 24.2.0 / pnpm 11.25.0，使用锁文件离线安装及严格 engine 检查通过。
- lint 无警告、TypeScript 检查通过，2 个测试文件共 12 项契约测试通过，生产构建成功。
- 使用真实 Edge 浏览器访问 Vite，通过代理得到临时 H2 后端健康接口的 HTTP 200 / UP 和 X-Request-Id。
- 正常访问时控制台没有错误；1440px 桌面与 390px 移动布局没有横向溢出。
- 未知嵌套路由显示 404，直接刷新仍可访问；返回首页恢复正常连接。
- 受控的加载、500、网络失败、10 秒超时场景验证通过；错误提示保留请求编号，解除故障后可重试连接真实后端。
- 前端 GitHub Actions 的 actionlint 静态检查通过；远端实际执行结果见对应 PR 和 Actions 页面。
