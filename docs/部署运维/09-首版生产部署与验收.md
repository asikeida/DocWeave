# 首版生产部署与验收

首版提供 JWT 登录、个人区域初始化、两份虚构示例预览、独立入库及正文阅读。生产注册默认关闭，仅预置受控体验账号。上传、向量化、检索、RAG 问答和企业成员管理尚未实现。

## 目录与网络

部署模板位于 deploy/production：Dockerfile（固定 JRE 基础镜像）、compose.yaml（生产后端）、nginx.conf（独立 HTTPS 站点）、runtime.env.example（配置占位）、backup.sh（仅备份 DocWeave 生产库）、.dockerignore（仅允许应用 JAR 进入镜像构建上下文）。

服务器部署目录 /opt/apps/docweave：runtime.env 权限 600；.env 只记录版本化镜像名 DOCWEAVE_IMAGE；releases/<版本>/ 保存 JAR、前端产物与镜像构建文件；current 软链接指向当前前端版本；backups 保存受限数据库快照。

宿主机 Nginx 的 443 提供页面和 /api 代理，后端只发布 127.0.0.1:8081。后端容器加入既有 projects-data 网络，通过 projects-mysql:3306 访问 docweave_prod。无需开放后端或数据库公网端口。生产不读取本机开发 .env，也不使用 SSH 数据库隧道。

## 构建与启动

先确认 PR 检查通过，再用 Java 21 打包 JAR，使用 frontend/package.json 指定的 pnpm 构建前端。将 JAR 命名为 app.jar 与 Dockerfile 放进版本目录，前端 dist 放到该目录 frontend-dist。

在版本目录执行 docker build -t docweave:<提交短哈希> .，并把 /opt/apps/docweave/.env 中 DOCWEAVE_IMAGE 设置为这个不可复用的版本名。真实数据库密码与至少 32 随机字节 Base64 JWT 密钥只写入服务器 runtime.env；同一运行环境复用密钥，不因重启更换。

首次启动前执行 backup.sh 或已有备份命令并确认成功；在部署目录执行 docker compose config --quiet、docker compose up -d --wait。Flyway 自动校验并应用 V1～V3，禁止 clean/repair 绕过错误。

体验账号通过现有显式开发初始化 CLI 非 Web 模式单次创建：使用同一生产数据库和密钥，临时 local profile、DOCWEAVE_BOOTSTRAP_ENABLED=true、随机用户名及强密码、spring.main.web-application-type=none，并将日志文件改到 /tmp。CLI 不启动 HTTP、不开放注册、不覆盖已有密码。完成后正式容器仅用 prod profile，绝不能以 local profile 对公网运行。凭据文件不上传 Git。

## HTTPS

部署环境必须提供覆盖访问用公网 IP 的受信任证书及自动续期。模板从 /etc/docweave-certs/fullchain.pem 和 privkey.pem 读取证书；可以使用现有集中维护的同 IP 证书，不重复修改其他站点。部署前验证证书有效期及 IP 匹配，nginx -t 通过后 reload，不重启其他应用。

当前服务器已有由另一套 ACME 任务维护的 IP 证书。DocWeave 使用独立证书路径的只读软链接复用现有文件，依赖原续期任务安装证书后 reload Nginx；不能仅凭当前证书有效就宣称续期全流程已验证。应持续检查证书到期日。

## 验收与回滚

服务器检查容器健康、/actuator/health、Flyway 历史及生产库账号范围；外部浏览器检查证书、页面、登录、刷新会话、区域初始化、示例入库与正文、退出后拒绝访问。生产注册应返回 REGISTRATION_DISABLED，管理与 Swagger 端点不公开。登录 Cookie 应带 Secure/HttpOnly。

回滚应用时还原 .env 的镜像版本与 current 软链接，然后 docker compose up -d --wait 并验证。只回滚到兼容当前数据库版本的代码；V3 增加字段后，旧 V2 写入代码可能不兼容。数据库回退必须单独评估备份恢复，不能用删除 Flyway 历史代替回滚。

backup.sh 使用服务器现有管理客户端配置，只导出 docweave_prod，gzip 校验成功后原子落盘，保留 14 天。可以用独立 cron 每日执行；本机快照不能替代异机备份，本轮未建立异机灾难恢复。不要使用 docker compose down -v。

## A1 文件管理分支的部署差异（Issue #29，审核版已部署）

本分支为后续上传增加 files:/data/docweave 持久卷、22m Nginx 请求体限制及默认关闭的生产写入开关。部署前创建私有 files 目录并授权 UID 10001，保持开发/生产目录隔离；2026-11-09 经用户授权部署工作区审核版，线上已应用这些改动；Git 尚未提交或合并。

启用原文件存储后，仅备份 MySQL 无法恢复文档。新 backup.sh 在文件目录存在时会短暂停止 DocWeave 容器，打包原文件与 SQL，成功后写同时间戳 complete 标记，并在退出时恢复容器；其他应用不停止。恢复必须使用同一个 complete 快照的 SQL/文件对，不能混用日期；备份期间本应用 API 会短暂不可用。脚本已在本次部署中执行，成功生成成对快照并恢复 DocWeave 服务；尚未进行数据库与文件的备份恢复演练。
