# 日志与请求追踪

## 当前实现

采用 Spring Boot 自带的 SLF4J / Logback，不另建模块日志文件或引入采集平台。
日志底座由三部分组成：Spring Boot 已通过 starter 引入 SLF4J / Logback，负责实际输出、滚动归档和 JSON 格式；`RequestIdFilter` 负责同步 HTTP 请求的 MDC 与响应头；`GlobalExceptionHandler` 负责记录未知异常的 ERROR 日志和堆栈。YAML 配置只负责输出方式，不会自动生成业务事件。

只有代码或框架实际记录的事件才会出现在日志中。当前不为每个成功请求打印访问日志，也不记录接口耗时；后续业务模块需要在关键节点显式记录事件。requestId 用于关联已有日志，不能保证每次请求都能搜到日志。

| 环境 | 输出 | 保留策略 |
| --- | --- | --- |
| local | 可读控制台和 `.local/logs/docweave.log` | 按天或单文件 10MB 归档为 gzip；归档最多保留 7 天、总计 100MB；启动时清理过期归档 |
| test | 默认可读控制台 | 不写入本地开发日志目录 |
| prod | ECS JSON 控制台 | 由部署环境的 Docker 日志驱动负责轮转，应用不额外写文件 |

容量限制针对归档；活动文件和异步清理可能短时超出归档上限。相对路径基于应用的工作目录。`.local/` 已被 Git 忽略。

## 查询方式

每个 HTTP 请求由服务端生成 requestId，在 X-Request-Id 响应头返回；可读日志的 requestId 字段与生产 JSON 中的 requestId 一致。请求结束或抛出异常后清理 MDC，避免线程复用串号。启动日志不属于 HTTP 请求，因此没有请求编号。

PowerShell 本地检索示例：

```powershell
Select-String -LiteralPath '.local/logs/docweave.log' -SimpleMatch '<request-id>'
```

按类名、级别和事件筛选可查看某个模块的问题。业务模块使用自己的类名 Logger；不为每个模块建立独立文件。

## 记录内容与级别

- INFO：已完成的关键业务事件，包含事件名和必要的 documentId、workspaceId 等业务标识。
- WARN：需要关注且可恢复的异常，例如业务操作被拒绝；不记录正常用户行为的每个细节。
- ERROR：未知或不可恢复错误，保留异常对象以定位根因；避免同一错误在多层重复记录。
- DEBUG：本地诊断；生产不默认启用，也不能用于输出敏感数据。

禁止输出密码、令牌、完整授权头、数据库凭据、请求或响应全文、私密文档内容。框架日志不会自动脱敏；业务代码不能将敏感输入拼入异常消息。该约定需要在代码审查中持续落实。

## Docker 部署约定（待应用容器阶段实施）

生产 JSON 由 Docker 收集。未来应用服务的 Compose 配置应包含：

```yaml
logging:
  driver: json-file
  options:
    max-size: "10m"
    max-file: "5"
```

这属于单个应用容器的日志设置，不修改服务器全局 Docker 配置。尚未创建应用容器，因此当前未在服务器应用这些设置。未来可用 `docker compose logs --since 30m <服务名>` 查看最近日志；长期集中存储在出现实际查询需求后再选型。

## 后续模块边界

Nginx 访问日志由 Nginx 独立维护。审计记录随账号、权限和删除操作设计，需有独立权限与保留周期。

后台任务、Kafka 和流式请求尚未实现；接入时必须明确 jobId、documentId 和请求上下文传递。不能依赖 MDC 在线程池中自动传播；需要显式传递并在任务结束后清理。接口文档中的 requestId 当前只保证同步 HTTP 请求链路。


## 验证边界

- `RequestIdFilterTests` 验证响应头、请求属性和 MDC 使用相同标识，不同请求不复用标识，正常结束和抛出异常后都清理 MDC。
- `DocWeaveApplicationTests` 模拟未知异常，验证返回 500、响应与 ERROR 日志包含相同请求标识、日志保留堆栈，响应不包含内部异常细节。测试端点只存在于测试源码中。
- 本地输出与生产 ECS 格式分别进行运行验证。生产格式的验证使用测试数据库和日志格式覆盖参数，不代表已在生产服务器部署。
- 本次滚动验证将阈值临时覆盖为 1KB，在 `.local/` 独立目录生成了 gzip 归档并成功解压；正式配置仍为 10MB。跨天触发、7 天保留和总容量清理不等同于小阈值滚动测试，需要在部署环境继续观察。
- 当前没有全局自动脱敏器、审计存储或异步上下文传播；记录内容的安全性仍依赖显式字段选择和代码审查。
