# 账号登录与验收

> Issue #13，M1.1，本轮交付登录身份闭环，尚未开放注册、个人组织、企业管理或知识库功能。

## 1. 本轮能够操作什么

前端新增 `/login` 与受保护的 `/account`。已有受控开发账号可登录、查看当前身份、刷新页面恢复登录及退出；错误提示保留 requestId。项目概览和健康检查仍可未登录访问。

登录用短期 JWT，刷新凭据只放 HttpOnly Cookie，后端在每次受保护请求检查当前登录与账号状态。完整取舍见 [JWT 决策记录](../决策记录/01-JWT登录与撤销策略.md)，接口见 [账号认证接口](../接口说明/02-账号认证接口.md)。

## 2. 数据库与迁移

本轮新增真实业务迁移 `V1__create_users_and_login_sessions.sql`，建立 users、auth_sessions、auth_refresh_tokens。JPA 使用 validate，不能依靠自动建表代替迁移。

先在隔离 MySQL 验证，再决定是否将本分支用于日常开发库。原来的骨架验收文档是当时的记录，“没有业务 V1”不再描述本分支现状。共享开发库升级前先备份，升级代码后 Flyway 会执行 V1；退回旧代码不自动删除新表，不可用 clean 或手工修改历史表模拟回滚。

本次另建隔离审核库和受限账号进行真实验证，原共享开发库没有应用本轮业务迁移。审核库不是真实生产库；不要存放真实用户资料。

## 3. 配置与启动

使用 Java 21，按 [本地开发环境](01-本地开发环境.md) 设置数据库环境变量。Spring Boot 不自动读取根目录 .env 文件。

local 首次启动会生成根目录被 Git 忽略的 `.env.auth-signing-key`，只保存开发密钥 Base64，不是环境变量脚本；不要删除后又期待旧 JWT 继续可验证。prod 必须通过环境变量提供 `DOCWEAVE_JWT_SECRET`，为至少 32 随机字节的标准 Base64；生产禁止关闭 Secure Cookie。密钥和初始化密码不能放在命令行参数、日志、可提交文件或前端变量中。

### 受控开发账号

仅 local profile 支持初始化。先通过当前进程环境设置 `DOCWEAVE_BOOTSTRAP_USERNAME` 与 `DOCWEAVE_BOOTSTRAP_PASSWORD`，后者至少 12 字符且 UTF-8 不超过 72 字节。账号名统一小写，格式规则见决策记录。

在项目根目录运行已构建 JAR（适用于 Windows、Linux、macOS）：

```text
java -jar target/docweave-0.0.1-SNAPSHOT.jar --spring.profiles.active=local --spring.main.web-application-type=none --docweave.bootstrap.enabled=true
```

该命令在无 Web 模式初始化后关闭，不提供 HTTP 注册接口。已有同名账号保持原密码，不能用它重置密码。完成后从当前终端清除初始化密码环境变量，再正常运行 IDE、Maven Wrapper 或 JAR。不要把初始化参数一直留在正常服务的运行配置中。

prod 不加载此入口，生产账号发放不属于本轮能力。M1.2 交付个人组织初始化和注册策略后再开放正式注册。

### 本次审核环境

真实审核用数据库与账号参数位于根目录被忽略的 `.env.auth-review`，只供本机使用，不提交或打印。该文件与已有 `.env.cloud-dev` 分开；里面的初始化账号只属于隔离审核库。

审核应用的端口、浏览器验证结果与是否保留运行在下方验收记录中说明，不把一次验证进程当作持久部署。若 SSH 断开，按云数据库文档恢复隧道，并使用该审核配置对应的本机端口。

## 4. 自动检查如何复现

常规验证不需要 Docker 或 SSH：

```text
./mvnw.cmd --batch-mode --no-transfer-progress verify
```

Linux/macOS 用 `bash ./mvnw`。默认使用 H2；MySqlAuthPersistenceTests 未配置隔离数据库时跳过，不能把跳过报告为真实 MySQL 已通过。

要运行真实 MySQL 验证，显式设置 `DOCWEAVE_TEST_MYSQL_URL`、`DOCWEAVE_TEST_MYSQL_USERNAME`、`DOCWEAVE_TEST_MYSQL_PASSWORD` 指向独立、可丢弃测试库。测试会建立表和插入测试账号，不能指向共享开发库或生产库。测试账号只需该测试库权限。

前端在 frontend 中运行 lint、typecheck、test、build。CI 增加临时 MySQL 服务与上述三个测试环境变量，使用明确标注的 CI 测试密码；这些不是服务器凭据，也不改变本机 Docker 使用方式。远端 CI 要推送后才能验证，本轮本地通过不等于远端结果。

本机审核入口为 `http://127.0.0.1:5175/login`，审核后端监听 `127.0.0.1:18085`，通过独立 SSH 转发端口 13308 访问隔离审核库。审核进程是临时本机环境，不是服务器上的应用部署，关闭电脑或进程后不会继续提供页面。

账号和密码分别读取根目录私密 `.env.auth-review` 的 `DOCWEAVE_BOOTSTRAP_USERNAME` 与 `DOCWEAVE_BOOTSTRAP_PASSWORD`，不要与数据库账号密码混用。常规开发配置 `.env.cloud-dev` 没有替换成审核库。

当前未开放注册、个人组织、企业权限、SSO 或生产部署；过期登录清理等限制见决策记录。没有新增专用启动脚本。代码保留在 feat/auth-login-账号登录 分支，等待人工审核，尚未 commit 或 push。
