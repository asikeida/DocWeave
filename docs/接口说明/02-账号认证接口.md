# 账号认证接口

> Issue #13，M1.1。返回成功资源本身；失败沿用 ApiError 与 X-Request-Id。所有请求使用 HTTPS，local 可通过同源 HTTP 代理开发。

## 浏览器调用顺序

1. GET `/api/v1/auth/csrf`，保存响应的 headerName 与 token 到当前操作内存。
2. POST 登录/刷新/退出时带上对应 CSRF 请求头，浏览器自动携带同源 Cookie。
3. 登录/刷新成功后把 accessToken 放内存，调用受保护接口时使用 `Authorization: Bearer <access-token>`。
4. 页面刷新后，通过刷新 Cookie 恢复短期访问令牌；退出必须等待后端确认，网络失败不能只清前端并宣称已退出。

不从请求体、URL 或 JavaScript 可读的持久存储提交刷新凭据。命令行或自动化调用也须保存 Cookie 并处理 CSRF。

## 端点

| 方法与路径 | 输入 | 成功响应 | 认证要求 |
| --- | --- | --- | --- |
| GET `/api/v1/auth/csrf` | 无 | 200：headerName、token | 可未登录；写入 CSRF Cookie |
| POST `/api/v1/auth/login` | username、password JSON | 200：TokenResponse，写入刷新 Cookie | CSRF；已有有效账号 |
| POST `/api/v1/auth/refresh` | 刷新 Cookie，不读取 JSON 中的令牌 | 200：TokenResponse，轮换刷新 Cookie | CSRF；未消费且未失效的刷新凭据 |
| GET `/api/v1/auth/me` | Bearer JWT | 200：id、username、displayName | JWT、登录记录及账号均有效 |
| POST `/api/v1/auth/logout` | 刷新 Cookie；也可携带有效 Bearer | 200：message=已退出登录，清除刷新 Cookie | CSRF；重复退出幂等 |

如果调用 logout 时主动发送一个已经失效的 Bearer，资源服务器会先返回 401。浏览器实现通过刷新 Cookie 退出，不向 logout 携带可能过期的访问令牌。

## 响应示例

```json
{
  "accessToken": "<短期访问令牌>",
  "tokenType": "Bearer",
  "expiresIn": 300,
  "user": {
    "id": "<账号ID>",
    "username": "<账号>",
    "displayName": "<显示名>"
  }
}
```

不返回密码、哈希、刷新原值、企业角色或知识库权限。id 为全局账号 ID，不是企业成员 ID。expiresIn 是本次令牌剩余秒数，不是登录记录总寿命。

## 失败语义

| 状态 | code | 含义 |
| --- | --- | --- |
| 400 | VALIDATION_ERROR / MALFORMED_REQUEST | 登录字段或 JSON 不合法 |
| 401 | INVALID_CREDENTIALS | 账号不存在、密码错误或停用，使用相同提示 |
| 401 | UNAUTHENTICATED | JWT、登录记录或刷新凭据无效；刷新失败会清除刷新 Cookie |
| 403 | ACCESS_DENIED | CSRF 校验失败或当前请求未获授权 |
| 429 | TOO_MANY_ATTEMPTS | 登录尝试超限，响应含 Retry-After |
| 503 | AUTH_UNAVAILABLE | Bearer 认证时无法核验数据库登录状态，拒绝访问 |
| 500 | INTERNAL_ERROR | 其他不可预期错误；返回安全信息，不泄漏内部异常 |

所有认证响应不缓存。资源服务器与 Controller 的拒绝都使用 ApiError；CSRF 拒绝不会由 MVC catch-all 改成 500。

## Swagger 调试

local 下打开 `/swagger-ui.html`，先执行 csrf 接口并把返回 token 填入登录、刷新或退出操作的 X-XSRF-TOKEN 请求头输入框，再执行请求；浏览器自动保留同源 Cookie。也可使用支持 Cookie 的 HTTP 客户端按上述顺序调试。

me 接口标注 bearerAuth，可在 Swagger 的 Authorize 输入访问令牌。prod 继续关闭 OpenAPI 页面。

## 后续边界

`/api/**` 的未公开接口默认要求已登录。组织、成员与资源权限由后续模块进一步检查，不把通过 JWT 等同于能访问任意企业数据。当前没有注册接口或可登录后创建组织的业务入口。

实现取舍见 [JWT 决策记录](../决策记录/01-JWT登录与撤销策略.md)，启动方式见 [账号登录与验收](../部署运维/07-账号登录与验收.md)。
