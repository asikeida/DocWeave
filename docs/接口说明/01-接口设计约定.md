# 接口设计约定

本文描述当前已经实现的 HTTP 基础约定。认证和业务资源接口将在对应里程碑实现后补充。

## 地址与版本

- 业务接口将使用 `/api/v1/` 前缀。
- OpenAPI JSON：`/v3/api-docs`（local、test）。
- Swagger UI：`/swagger-ui.html`（local、test）。
- 健康检查：`/actuator/health`。

生产环境关闭 OpenAPI 与 Swagger UI；当前仅公开健康检查端点，其他 Actuator 端点不通过 Web 暴露。

## 成功响应

成功响应直接使用合适的 HTTP 状态码和资源 DTO。骨架阶段不引入统一成功包装，以保留 HTTP 的原生语义。

## 错误响应

所有框架校验错误、格式错误和未处理异常都返回 JSON：

```json
{
  "code": "VALIDATION_ERROR",
  "message": "请求参数校验失败",
  "requestId": "d4d6a62d-0eaf-4b03-a83f-0e83b9649ef4",
  "timestamp": "2026-10-23T06:00:00Z",
  "violations": [
    {
      "field": "title",
      "message": "不能为空"
    }
  ]
}
```

- `code`：稳定的、面向调用方的错误码。
- `message`：可直接展示给用户的简短说明。
- `requestId`：服务端为单次请求生成的标识，同时以 `X-Request-Id` 响应头返回。
- `timestamp`：服务端生成错误的 UTC 时间。
- `violations`：字段校验失败时列出字段及原因；其他错误为空数组。

服务端不会在该响应中返回堆栈、SQL、文件路径、密码或令牌。

## HTTP 状态码与请求追踪

Spring MVC 的标准错误保留原有 HTTP 状态码和必要响应头，例如路径不存在为 404、方法不支持为 405（保留 Allow 头）、媒体类型不支持为 415。响应体统一采用 ApiError，未知异常返回 500。

服务端日志通过 MDC 的 requestId 字段输出请求标识。当前由服务端生成标识，不直接信任调用方传入的 X-Request-Id。后续接入网关时再约定可信来源、长度和字符范围，避免任意输入进入日志。
