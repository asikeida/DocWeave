# 小文件上传、下载与删除（Issue #29）

> A1 文件管理（Issue #29）已完成本地与线上验证，2026-11-09 部署审核版。当前只保存原文件，不解析、不索引、不问答。

## 1. 调用顺序

先按认证文档登录取得 Bearer JWT。写操作先 GET /api/v1/auth/csrf，保留同一 Cookie 会话，并将响应 token 放入 X-XSRF-TOKEN；上传额外发送 Idempotency-Key（8～80位 ASCII 字母、数字、下划线、连字符，建议 UUID）。查询本人知识库，目标必须是本人当前有效区域内的库。

| 方法与路径 | 请求/成功响应 |
| --- | --- |
| POST /api/v1/knowledge-bases/{id}/documents | multipart/form-data，file 为文件字段；新建201，重复内容/安全重放200；JSON 包含 document 与 replayed |
| GET /api/v1/knowledge-bases/{id}/documents | 现有列表扩展来源 source、byteSize、mediaType、createdAt |
| GET /api/v1/documents/{id}/download | 返回二进制 attachment、实际 MIME、Content-Length、no-store；Bearer 必须携带 |
| DELETE /api/v1/documents/{id} | 需要 CSRF；首次或本人已删除文档均204，无权或未知404 |
| GET /api/v1/documents/{id} | 示例正文照旧；未解析上传文档409 DOCUMENT_NOT_PARSED，不能把它当成上传失败 |

上传成功响应示意（ID 为占位符，不是可直接请求的真实资源）：

```json
{
  "document": {
    "id": "<document-id>", "knowledgeBaseId": "<knowledge-base-id>", "title": "资料.md",
    "sampleKey": null, "seedVersion": null, "sha256": "<server-sha256>",
    "indexState": "NOT_INDEXED", "source": "UPLOAD", "byteSize": 97,
    "mediaType": "text/markdown", "createdAt": "<ISO-8601 timestamp>"
  },
  "replayed": false
}
```

SAMPLE 保留 sampleKey/seedVersion，文件专属字段可为空；UPLOAD 不编造示例身份，原文件正文仍为空。前端区分“查看示例正文”和“下载已保存原文件”。

## 2. 文件与额度

支持有合法 PDF 结构的 PDF、UTF-8 TXT/Markdown。PDFBox 3.0.8 做结构和加密检查，最多500页，不提取正文；扫描件可能上传成功，但后续解析阶段尚未实现，不能称可检索。文件名最大160字符，拒绝路径、控制字符和不支持扩展名；声明 MIME 与扩展名不符拒绝，服务端复核 PDF 魔数或文本编码。

默认：20MiB/文件、100MiB/上传人活动文件、每人2个持久处理中上传、每日30次已预留尝试（UTC 日期）；校验阶段另有进程内2个并发槽，非法文件不计持久化日额度。失败和删除不返还日次数。预留大小与已用容量一起算，用户行锁防并发超额。

同库重复需要完整接收并由服务端计算 SHA-256 后去重，**不是秒传**。上传前仍需容量预留，因此容量已满时重复内容也可能先被拒绝；后续可在上传增强阶段改善，当前不绕过配额检查。

## 3. 幂等、失败与删除

幂等范围为上传人+key；指纹包括目标库、文件名、大小、实际类型与服务端摘要。同键不同内容/目标409 IDEMPOTENCY_CONFLICT；同键正在处理409 UPLOAD_IN_PROGRESS；完成后重放先重新鉴权并确认文件存在，不因 COMPLETE 绕过删除或权限。

网络断开、超时或响应丢失：保留原文件与原 key 重试，可能得到此前已经保存的文档。明确记录失败的 key 返回409 UPLOAD_PREVIOUSLY_FAILED，需换新 key 重试；页面在明确失败后自动换键，在未知网络结果时保留键。

上传预留提交后才写 .part，核对大小和摘要后原子发布 .bin，再短事务创建文档及版本。存储失败或确认事务失败进入持久 FAILED/清理待办；数据库不可用时保留 WRITING，由15分钟租约到期恢复。进程重启不依赖 Redis 恢复状态。

删除先逻辑失效并清除活动摘要占位，同时提交清理待办；下载和列表立即拒绝/隐藏。删除已授权的在途下载不承诺中途截断；新请求按当前状态鉴权。当前一个版本一份文件，不做共享 blob 引用计数。

worker 每30秒扫描：最多20个过期上传人、20个清理对象；任务行锁避免重复清理。删除失败每60秒再试，自动最多8次，last_error_code 与 attempts 保留供人工处理。清理队列积压可能需要多个周期，不承诺立即释放物理磁盘。不能随意删整个文件目录。

## 4. 错误举例

| 状态 | 错误 |
| --- | --- |
| 400 | EMPTY_FILE、INVALID_FILENAME、INVALID_FILE、INVALID_IDEMPOTENCY_KEY |
| 403 | DOCUMENT_WRITES_DISABLED、缺失/无效 CSRF |
| 404 | RESOURCE_NOT_FOUND、ORIGINAL_FILE_UNAVAILABLE（示例没有原文件） |
| 409 | IDEMPOTENCY_CONFLICT、UPLOAD_IN_PROGRESS、UPLOAD_PREVIOUSLY_FAILED、UPLOAD_EXPIRED、DOCUMENT_NOT_PARSED |
| 413/415 | FILE_TOO_LARGE 或框架请求体超限 / UNSUPPORTED_FILE_TYPE、INVALID_TEXT |
| 429 | UPLOAD_RATE_LIMITED、STORAGE_QUOTA_EXCEEDED |
| 503 | STORAGE_UNAVAILABLE，包括底层对象缺失 |

错误统一 ApiError 和 requestId；不返回存储路径。JSON 解码失败、超时和取消在前端有明确提示，不伪装上传成功。

## 5. 数据库与配置

V4 新增 document_files、document_uploads、document_cleanup_jobs；documents 增加来源、活动文件摘要唯一约束；示例标识和版本正文改为可空并加来源组合约束。旧 V1～V3 未修改。保留文档/版本复合归属外键，保留原示例唯一约束和 NOT_INDEXED。

配置集中于 docweave.documents：root、write-enabled、max-file-bytes、max-user-bytes、max-concurrent、daily-limit、upload-lease。worker-enabled 可在测试中关闭；自动测试使用临时目录及一次性 MySQL 库，不能对共享开发库运行清库测试。

local 开放文件写入，默认 .local/files；prod 默认关闭，根目录 /data/docweave，仅在独立账号/配额/备份均就绪后显式开启 DOCWEAVE_DOCUMENTS_WRITE_ENABLED。开发与生产不得共用目录。生产模板新增 ./files 挂载，需提前 mkdir 并将目录授权给容器 UID 10001，避免 Docker 自动创建 root 目录导致写入失败。

Spring 限制20MB文件/22MB请求，Nginx 模板22m。线上审核版已应用这些限制；切勿只提高业务限制却不改反向代理或临时目录容量。

备份脚本改为：若存在文件目录，停止**仅 DocWeave 容器**，导出 SQL 与文件快照，完整成功后写同时间戳 complete 标记，最后恢复容器；这是单机简单一致性方案，有短暂停机。仅 complete 的配对快照可以整套恢复。保留14天、本机备份不等于异机灾难恢复；生产已执行新版脚本，完成配对备份及容器停止后恢复服务；尚未进行数据库与文件的备份恢复演练。

## 6. 审核环境与已知限制

本机前端 http://127.0.0.1:5188/personal，后端127.0.0.1:18098；两者仅本机监听。仍需保持13306 SSH隧道。开发库已迁移到V4；审核凭据位于被忽略的根目录 .env 的 DOCWEAVE_REVIEW_USERNAME/PASSWORD，不进入文档或 Apifox。

开发库保留两份示例和一份虚构“审核资料.md”，并有一份已逻辑删除的测试文件及其清理痕迹，便于观察各表关联。文件在 .local/files 按UUID存储，原文件名仅在元数据中。V4 后旧代码可能不兼容新列表字段/表结构，审核使用当前分支，不随意退回旧业务分支直接写此库。

未实现：解析/向量化/问答、病毒扫描、分片/秒传/续传、文件版本覆盖、跨租户物理共享、公开注册。PDF 仅做同步结构检查与页数/大小限制，复杂文档解析隔离属于后续阶段；不要将此初版宣称为完整不可信文档沙箱。

线上已开放上传界面：个人页面自动展开第一个知识库；上传文件显示下载、删除按钮，示例文档显示查看正文入口。上传原文件暂不支持在线预览。

补充：SAMPLE 的 sha256 标识示例正文，UPLOAD 的 sha256 标识原文件字节；后续解析正文摘要应另行设计，不能在原文件校验字段中悄悄替换含义。90项后端测试覆盖存储实例重建读取；线上部署还验证了容器停止后恢复健康，未执行带在途上传的进程故障演练。
