# A2 第二阶段：持久任务与正文落库（Issue #34）

> 2026-11-09：开发分支 feat/processing-持久解析任务，已验证，待用户审核，未提交/推送/部署。本阶段接续已通过 PR #33 合并的执行器；A2 总任务 #31 保持打开。任务状态接口、手动重试接口和前端正文阅读在下一阶段实现。

## 1. 本轮完成的闭环

新文件上传确认事务创建文档/版本/原文件记录，同时插入 PENDING 解析任务。后台独立线程领取任务、用现有子 JVM 提取正文，最后在一个事务保存正文、位置、正文摘要和 SUCCEEDED。任务与文件确认任一失败，整个确认事务回滚，原文件进入 A1 持久清理流程。

原 sha256 仍是原文件字节摘要；新增 content_sha256 是规范化正文摘要。解析成功仍为 NOT_INDEXED，不代表能够搜索或问答。

同版本/parser_version 的任务有唯一约束，重复上传重放或重复排队不会重置尝试次数。每用户最多 10 个 PENDING/RUNNING 待办，满额返回 429 PROCESSING_QUEUE_FULL；同内容复用既有文档不新增任务，历史无任务文档不在启动时自动扫描入队。

## 2. 任务状态、租约与权限

PENDING → RUNNING → SUCCEEDED / FAILED / CANCELLED。临时失败最多 5 次，重试延迟 30 秒、2 分钟、10 分钟、30 分钟；无有效文字、损坏、超限、超时等不自动重复处理。自动恢复保留尝试次数，不能清零来绕过限额。

每次领取生成新的 claim_token；续租、失败更新、正文发布均复核当前 token、RUNNING 与有效租约。过期任务先回到有退避的 PENDING 或最终 FAILED；旧执行器迟到不能写回。

锁顺序为账号、文档、任务，发布时还锁定并复查组织/成员/空间授权和知识库。删除文档会取消未完成任务，并与最终发布串行化。停用或撤权后取消任务，原文不发布；数据库不可用时保留租约等待恢复，不把“无法检查权限”当作允许。

调度器只投递一个任务，专用执行线程解析，另一个专用线程续租，避免解析阻塞 A1 其他定时任务。迟到心跳不会中断同一线程后来执行的任务。

父进程消失或子进程运行超过本地截止时间，子 JVM 看门狗结束自己。暂存按父进程 PID/启动时间分实例，旧目录至少等待 3 分钟，确认所属父/子进程均已退出才清理；未知身份保留，不按 PID 猜测后终止其他进程。

## 4. 配置与审核入口

配置位于 application.yaml 的 docweave.processing：worker-enabled、root、timeout、lease、heartbeat、max-pending-per-user、max-attempts、poll-delay-ms。默认 worker 关闭，通过 DOCWEAVE_PROCESSING_ENABLED 显式启用；关闭时保留已排队任务。

默认单次 60 秒、租约 120 秒、心跳 20 秒；配置类验证超时、续租与尝试次数边界。parser_version=text-v1 是代码算法标识，不作为任意运行时开关。

本地审核后台为 http://127.0.0.1:18108，使用固定开发库和现有被忽略 .env 的审核账号。原 18098 的旧 A1 审核进程已核对身份后停止，避免旧代码继续写新结构。前端未改，不提供本轮任务按钮；可用 Apifox 或既有接口查看解析成功文档。

POST 上传仍返回文件保存结果；GET /api/v1/documents/{id} 对解析成功上传返回正文及真实 UPLOAD 元数据，未完成仍 409 DOCUMENT_NOT_PARSED；下载和删除契约不变。没有新增 HTTP 路径。
