# 骨架阶段验收清单

本清单细化“项目骨架与模块开发路线”中的第一阶段。完成本清单后，才进入账号与工作空间模块。

## 目标

在尚未开发业务功能时，建立一个可以安全迭代、可追踪、可诊断的应用底座。

## 工作项

### 1. 仓库与协作

- 根目录 `AGENTS.md`、`README.md` 和 AI 开发规范齐全。
- 正式文档与本地临时笔记有明确边界。
- Git 分支、提交、Issue、PR 和发布规则可执行。

### 2. 本地环境与配置

- `compose.yaml` 仅提供本阶段需要的 MySQL。
- 提供 `.env.example`，真实本地配置不提交。
- 建立 `local`、`test`、`prod` 配置边界。
- 新人按文档可以启动依赖、后端和测试。

### 3. 数据库演进

- 接入 Flyway。
- 第一个包含持久化业务表的交付必须同时提交 `V1__...sql` 迁移脚本与迁移说明；在此之前不创建空迁移。
- 禁止依赖生产环境自动建表或自动修改表结构。

### 4. API 基础

- 建立统一参数校验和异常处理。
- 定义并验证一套稳定的错误响应格式。
- 接入 OpenAPI 与 Swagger UI。
- 为接口文档页面提供本地访问说明。

### 5. 日志、健康检查与安全底线

- 建立日志格式、级别和敏感字段脱敏规则。
- 为请求加入可关联的请求标识。
- 使用 Actuator 提供最小健康检查端点。
- 仅暴露必要端点，避免公开配置、环境和敏感指标。

### 6. 质量与自动化

- 至少具备可重复执行的测试命令。
- 建立 GitHub Actions：后端编译和测试。
- 为文档、配置、数据库和 API 的改动定义最小验证方式。

## 验收结果

以下条件同时满足时，骨架阶段才算完成：

1. 在干净本机环境中可按 README 启动。
2. 数据库结构通过 Flyway 管理。
3. 健康检查、日志和 Swagger UI 可用且无敏感信息泄漏。
4. CI 可以自动编译和测试。
5. GitHub 上能通过 Issue → 分支 → PR → 合并记录一个完整的小型交付闭环。
