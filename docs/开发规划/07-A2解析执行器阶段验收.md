# A2 第一阶段：解析执行器验证（Issue #31）

> 2026-11-09：本阶段代码与验证已完成，待用户审核；A2 的持久任务、数据库迁移、HTTP 接口和页面尚未实现。本轮没有发布，线上仍为 A1。

## 1. 为什么先做这一步

PDF 解析不应长期占用处理登录、上传等请求的主服务。线程取消不能保证解析库立即停止，因此先验证独立 Java 进程的启动、结果交付、超时终止和资源回收，再接入持久任务。

采用同一个应用 JAR 的 --parse-document 模式；该分支在 SpringApplication.run 之前执行，不创建 Spring 上下文、数据库连接或 HTTP 端口。普通启动模式保持不变。Maven 明确指定正常服务的 mainClass，不新增依赖或第二套应用工程。

## 2. 已实现的行为

| 能力 | 实现 |
| --- | --- |
| TXT/Markdown | 严格 UTF-8，去开头 BOM，CRLF/CR 规范化为 LF；只保留文字，不渲染 HTML |
| PDF | 文本层逐页提取，最多 500 页；保留混合文档的空页位置，全无有效文字则明确失败 |
| 正文与位置 | 规范化正文及 UTF-16 左闭右开跨度；PDF 页码、文本行号从 1 开始；长文本拆成有界阅读段 |
| 输入复核 | 服务端流式校验预期长度和 SHA-256，最多 20MiB，不接收客户端物理路径 |
| 输出限制 | 提取缓冲最多 2MiB UTF-8，单阅读段最多 48KiB；总位置数有上限，不先无限读入再判断 |
| 进程边界 | 每个 ParserProcess 实例最多一个执行器；后续应由单例 worker 复用，不按任务创建多个实例绕过并发限制 |
| 资源参数 | 子 JVM 初始堆 16MiB、最大堆 128MiB、元空间 96MiB、直接内存 16MiB；堆并非总进程内存 |
| 超时与取消 | 执行时间最多 60 秒；终止先正常请求，最多等待 2 秒，再强制终止最多等待 5 秒；终止确认有额外宽限，不宣称总调用严格 60 秒 |
| 环境与日志 | 子进程环境只保留必要系统目录及受控临时目录变量；不传父进程的数据库/JWT/代理/JVM 注入环境，丢弃子进程标准输出和错误流 |
| 交付协议 | 有版本和大小限制的二进制文件，完整写入后原子发布；不用 Java 对象反序列化，不把 stdout 当正文协议 |
| 清理 | 先确认子进程退出再清理本次 attempt 目录；不跟随符号链接，Windows 句柄释放有界重试 |

父进程复核结果文件长度、协议头、错误码、UTF-8、位置数量、下标范围、代理对边界与单段大小。错误使用稳定代码，不把 PDF 库异常、正文或实际路径放进结果协议。若操作系统无法确认子进程退出，该实例停止接受新工作并保留目录，不能假装已回收。

48KiB 是内部原始文本段上限，不是未来 HTTP JSON 的响应上限；A2 后续接口仍需计算 JSON 编码后的实际字节，不能忽略转义和元数据开销。

## 3. 实际验证

- 根目录完整 mvn test：102 项发现，75 项执行通过，27 项真实 MySQL 因未配置连接跳过，无失败；本阶段未修改数据库。新增 12 项测试全部通过：格式、空页/扫描类无文字、加密、页数、错误编码、Unicode 位置、输出超限、结果损坏、并发限制、超时/中断后进程退出、环境白名单及临时目录回收。
- Windows 打包 JAR 验证 8 项通过；Linux 一次性容器中的同一产物验证 8 项通过，包含约 1.4MB 的中英文/emoji 文本及三页 PDF。
- Linux 容器：Java 21 JRE、只读文件系统、UID 10001、1GiB 内存、1 CPU、128MiB tmpfs、不开放端口、网络禁用；使用合成环境变量验证父级密钥不会继承。
- Linux 样例组 cgroup 内存峰值 114495488 字节（约 109MiB），退出码 0，未被 OOM 杀死。测试容器及远端临时包已删除，线上应用容器 ID 和健康状态保持不变。

这里的内存峰值只代表该样例组，父进程没有启动完整 Spring 服务，不是实际应用负载基准。尚未证明主服务、并发上传、最复杂 PDF 和解析执行器共同运行时的内存与临时盘余量。接 worker 前必须在真实限制下补测，不据此降低线上内存或提高并发。

复验方式：使用 JDK 21 运行 mvn -Dtest=DocumentTextParserTests,ParserProcessTests test。正常打包仍用 mvn package；不要在正在运行的审核 JAR 上覆盖打包，先使用独立构建目录。此次完整可执行 JAR 在被忽略的 .local/a2-build 中构建，仓库与依赖相同，仅构建路径隔离。

## 4. 当前限制与下一阶段

- 没有 V5，没有解析待办、租约或重试接口，没有自动解析新上传文件，页面还不能查看上传正文。
- 目前只是执行器超时/中断机制，不等于已实现“服务被杀后任务恢复”。进程意外退出后的孤儿执行器与残留目录，需要持久任务的租约、回收及部署生命周期一起处理。
- 同 UID 子进程不是完整安全沙箱；本轮测试容器的 network none 不代表未来主服务内的子进程天然没有网络访问能力。
- PDF 原文件的 A1 同步结构检查仍在原上传流程里，这一步没有把它移入执行器，不能声称所有不可信 PDF 处理都已隔离。
- 长正文、复杂字体、图片、极端压缩对象及磁盘满场景仍需扩充样例。没有新增 OCR、病毒扫描或 PDF 原版预览。
- 执行器目前是可验证的普通 Java 类型，尚未注册为后台任务 Bean；资源可配置项在后续接 worker 时再集中到 YAML 并约束安全上限。

审核本阶段后，按实施计划继续 V5、原子排队、任务 fencing、删除竞争、状态/正文接口和最小页面。不得将本页的“执行器已验证”表述为“A2 已上线”。
