## 1. 先用一个例子说明这轮要做什么

你上传一本《员工手册.pdf》：

1. 上传成功，原文件可以下载；列表显示“等待解析”。
2. 后台任务读取文件，逐页提取文字，列表变为“解析中”。
3. 成功后可以点“查看正文”，按页阅读，例如“第 3 页：报销申请应在出差结束后提交”。
4. 如果它是只有图片的扫描件，显示“未提取到可用文字，暂不支持 OCR”，不能显示解析成功。
5. 如果临时读不到文件，记录失败原因；符合条件时自动或手动重试。

这一轮的产出是“原文件 → 可阅读正文和来源位置”。向量、搜索和问答在 A3/A4 完成；解析成功仍然是 NOT_INDEXED。

## 2. 已核实的代码起点

| 当前事实 | A2 如何接续 |
| --- | --- |
| V4 已应用，原文件通过 FileStorage 读取 | 复用受控存储接口，不接收客户端磁盘路径 |
| document_versions.content_text 为可空 TEXT | 新增 V5 扩容为 MEDIUMTEXT，并由应用限制正文大小 |
| 上传版本 sha256 是原文件字节摘要 | 保留原含义，新增独立正文摘要，不覆盖原 SHA-256 |
| index_state 约束只允许 NOT_INDEXED | 本轮不改为 READY，不把解析状态塞进索引字段 |
| 未解析上传文档 GET 详情返回 DOCUMENT_NOT_PARSED | 成功后复用详情读取正文，未成功时保留明确 409 |
| 当前正文详情用了旧的示例摘要构造方式 | 接入上传正文时补齐 source、大小、MIME 等真实元数据，防止把上传文档当示例 |
| 示例正文已经存在，无 PDF 原文件 | 保留原文，直接视为已有正文，不为示例建立虚假解析任务 |
| A1 已有上传恢复和文件清理任务 | 保持职责独立：新建解析任务表，不用清理队列承载解析 |

V1～V4 一律不改写；V5 是计划编号，实施时先确认没有其他已占用的新版本。

## 3. 本轮范围和暂不做的内容

本轮包含 PDF 文本层提取、UTF-8 TXT/Markdown 正文、持久化任务、状态查询、受控重试、故障恢复、正文按页/位置读取和最小前端操作。

不包含 OCR、Word/Excel、表格结构还原、图片理解、Markdown HTML 渲染、文本语义切片、Embedding、ES、模型问答、文件覆盖与版本上传、企业权限后台、S3、秒传和断点续传。不新增 Kafka、Redis 队列或新的常驻中间件。

“PDF 文本提取”不保证复杂多栏、表格、阅读顺序和公式完全准确。混合扫描 PDF 允许返回有文字的页，同时明确提示哪些页为空；整份没有有效文字则失败。不能把空白页简单等同于扫描页。

## 4. 用户看到的界面

进入个人资料后继续自动展开第一个知识库：

| 情况 | 页面文字与操作 |
| --- | --- |
| 新上传、已排队 | 等待解析；保留下载、删除 |
| 任务执行中 | 正在解析；保留下载、删除，不提供虚假的百分比 |
| 解析成功 | 正文已生成，尚未索引；查看正文、下载、删除 |
| 可重试失败 | 简明原因、已尝试次数、重试按钮；保留下载、删除 |
| 不支持或达到重试上限 | 原因和处理建议，不显示无效的重试按钮 |
| A1 历史上传、未建任务 | 尚未解析；显示“开始解析” |
| 原有示例 | 示例正文可查看，尚未索引；不显示原文件下载或解析按钮 |

正文区支持上一页/下一页、页号和空页提示；TXT/Markdown 按受限文本段展示并标注原始行号范围。内容只以文本显示，不使用 v-html。刷新能恢复状态，切换知识库/退出登录时停止轮询。仅任务未结束时每 3 秒查询当前可见文档，页面隐藏时暂停，错误退避，避免每份文件各开永久定时器。

## 5. 模块职责与调用链

在现有模块化单体中按实际需要增加 ingestion：

| 职责 | 归属和作用 |
| --- | --- |
| 原文件、下载、删除 | document，继续负责文件生命周期和现有鉴权 |
| 排队、领取、租约、重试 | ingestion 的 service/repository，MySQL 保存权威状态 |
| 格式提取 | ingestion 的 parser，PDF/TXT/MD 实现统一有界结果契约 |
| 后台调度 | ingestion worker，有界领取任务并启动解析执行器 |
| 任务状态和开始/重试接口 | ingestion controller/dto，复用 JWT、CSRF、ApiError、requestId |
| 文档摘要、正文读取 | knowledgebase，返回真实来源、处理摘要与正文位置 |

不要在 Controller 中解析 PDF，不在请求线程等待整个解析完成，不持有数据库事务做文件提取。不预建所有可能的 parser、工具类或空包。

新上传最终确认事务同时写“原文件文档记录 + 解析待办”。事务失败两者一起回滚，沿用 A1 对原文件的清理与恢复。上传接口仍表示“文件已保存”，不承诺正文已生成。禁用 worker 时任务保留等待，不伪造成功。

## 6. 状态、幂等与重试规则

任务状态：PENDING（待执行）→ RUNNING（执行中）→ SUCCEEDED / FAILED / CANCELLED。临时错误可转回 PENDING 并设置下次时间，终态保留原因。列表中的 NOT_REQUESTED 是“没有任务”的展示值，不是额外任务行。

- 每个文档版本和固定 parser_version 只允许一个任务。重复提交“开始解析”返回现有任务，不重复插入。
- 领取时生成新的随机 claim_token；每次领取都不同。完成、续租、失败更新必须同时匹配任务、RUNNING、claim_token 和有效租约。
- 一个任务累计最多尝试 5 次，自动重试和手动重试共用该计数；手动操作不能清零来绕过上限。
- 初始建议：临时失败延迟 30 秒、2 分钟、10 分钟、30 分钟后重试；实际由 attempt_count 决定，不无限循环。
- 文件损坏、加密、不支持编码、无可用正文、输出超限为不可自动重试错误；缺文件返回明确原因，不反复空转。重试能力按错误分类和次数由服务端给出 canRetry。
- 超时和资源限额属于受限失败，首版不自动重复攻击性文档；界面提示更换或缩小文件。
- 成功任务不提供强制重解析；未来更换 parser_version 是新一轮迁移/重处理设计，不在本轮扩展。
- 请求响应丢失后，再查当前任务即可。重试接口锁定现有任务；重复点击不能创建两个并行任务。

## 7. 事务、租约与删除竞争

1. 短事务核对账号、个人组织、成员、空间、知识库、文档和版本状态，领取一个到期任务；记录 claim_token、开始时间、租约和尝试次数。
2. 事务提交后读取受控存储对象，在独立解析执行器中处理；不持有行锁等待文件 I/O。
3. 主进程按 claim_token 续租。建议租约 120 秒、心跳 20 秒、单次解析硬超时 60 秒；续租失败停止执行并放弃结果，不凭旧内存状态写回。
4. 完成时开启短事务，重新核对归属、账号/成员有效性、未删除、目标版本、任务 token 和租约；满足条件才原子写正文、位置与 SUCCEEDED。
5. 进程退出后，扫描过期 RUNNING；按错误/次数决定重新排队或 FAILED。旧执行器即使迟到，也不能覆盖新 token 的结果。

删除事务标记文档失效，并取消未终结解析任务；与最终发布使用同一文档行锁。即便解析已经成功，删除仍立即阻止正文、位置和下载读取。若正文提交先发生，随后删除隐藏它；若删除先发生，解析结果不得提交。原文件由 A1 清理队列回收，解析执行器遇到删除或对象消失应安全终止。

锁顺序在实施时对齐现有路径，原则为账号 → 文档 → 任务，不在 worker 使用反向锁顺序。SQL 写入带 tenant_id、document_id、version_id 的一致性条件；不能只按 UUID 更新。任何授权检查失败均不发布结果，不能降级为忽略成员状态。

## 8. 数据模型提案（V5）

本节是字段设计，不是已执行 SQL。最终约束、索引和 MySQL/H2 兼容性在实现审核中展示。

### 8.1 document_versions

- content_text：TEXT → MEDIUMTEXT，仍允许未解析时为 NULL。
- 新增 content_sha256、parser_version、parsed_at；原 sha256、index_state 不变。
- 正文统一换行为 LF，PDF 页间使用固定分隔符；摘要计算规则固定并有测试。
- 旧示例正文不重新生成；历史摘要和来源保持。新字段可空以兼容既有数据，不在迁移里假造解析时间。

### 8.2 document_processing_jobs（新增）

记录 id、tenant_id、document_id、version_id、parser_version、status、attempt_count、claim_token、lease_expires_at、next_attempt_at、last_error_code、created_at、started_at、finished_at、updated_at。

唯一键 (tenant_id, version_id, parser_version)，归属外键防止跨组织绑定；索引覆盖 (status, next_attempt_at)、(status, lease_expires_at)。错误仅存稳定代码，不存原文、绝对路径或堆栈。

### 8.3 document_text_locations（新增）

保存 tenant_id、version_id、sequence_no、page_number（PDF）、start_line/end_line（文本）、start_offset/end_offset 和必要的空页标记。联合唯一键按版本和顺序，复合外键绑定同组织版本。

正文以 document_versions.content_text 为本轮权威副本；位置表只存跨度，避免重复保存每页全文。offset 明确定义为规范化正文的 Java UTF-16 下标，左闭右开；PDF 页码从 1 开始，文本行号从 1 开始。中英文、换行、emoji 和空页都要有切片一致性测试。

这些跨度用于阅读和后续追踪来源，**不等于 RAG chunk**。A3 文本切片应保存独立 chunk_id、切分版本，并映射回本文位置。

## 9. 解析执行器与资源边界

初始提案：每文件沿用 20MiB/500 页限制；解析并发 1；规范化正文 UTF-8 总量最多 2MiB；一次正文读取最多 64KiB UTF-8，过长的单页拆成连续阅读段并保留相同 page_number。超过总量直接明确失败，不默默截断后宣称完整成功。

PDFBox 复用现有依赖。TXT/Markdown 严格 UTF-8 解码，BOM 处理及换行规范化写测试；按行号保留位置，不执行 Markdown 中的 HTML、脚本或外链。

不能仅用 Future.cancel/线程 interrupt 宣称 PDF 解析可以被硬停止。计划使用受限子 JVM 执行文件提取：主进程调度任务，子进程只接收受控临时输入与结果路径，不接收数据库/JWT 密钥；参数使用 ProcessBuilder 参数数组，不拼 shell 字符串。子进程超时先结束，等待退出，必要时强制结束，再清理暂存。完成标记、输出长度和结构由主进程校验，不信任任意子进程 JSON。

实现第一步必须验证“本地 + Linux 容器”下的子 JVM 打包/启动、128MiB 初始堆上限、内存实际开销、60 秒终止和结果清理。堆上限不等于进程总内存；主/子 JVM 共用当前容器内存额度，必须测量后决定是否调整主堆或容器限制。不能上线后才发现两个 JVM 抢占内存。

临时空间与产物合计也要有界，先评估当前容器 /tmp 128MiB 是否容纳输入、PDF 临时数据与输出；不足时提出具体变更和验证。子进程不得继承完整生产环境变量，不可访问任意调用方路径，不对外提供解析服务端口。子 JVM 与主服务同用户运行仍不构成完整安全沙箱，首版只用于受控体验文件，不宣称隔离了所有恶意文档风险。

若该验证无法在现有部署资源内稳定通过，先报告结果并调整本计划，不静默改为“在线程里跑且声称支持硬超时”。解析失败不可影响其他文档的 API 健康。

## 10. 接口提案与兼容性

所有接口均按当前有效权限读取；写接口要求 CSRF，错误带 requestId，无权和未知资源统一 404。任务 ID、文件摘要不能作为授权凭据。

| 方法与路径 | 预期契约 |
| --- | --- |
| GET /api/v1/documents/{id}/processing | 返回当前任务、状态、尝试次数、安全错误代码、canRetry；历史无任务返回 NOT_REQUESTED |
| POST /api/v1/documents/{id}/processing | 对历史未处理上传创建待办，首次 202；已有任务 200，不重复创建；示例不受理 |
| POST /api/v1/documents/{id}/processing/retry | 失败且可重试时排队 202；PENDING/RUNNING 返回已有任务 200；成功/不可重试/超上限 409 |
| GET /api/v1/documents/{id}/text?after=...&limit=... | 受限读取正文段及页码/行号，返回 nextCursor；游标绑定文档版本/序号，参数校验，不提供任意路径读取 |
| GET /api/v1/documents/{id} | 保持 DocumentDetail 契约；成功上传也能得到真实 source=UPLOAD 元数据及有界总正文，未成功仍为 DOCUMENT_NOT_PARSED |
| 现有文档列表 | 添加 processingState、canRetry 等摘要字段，indexState 继续 NOT_INDEXED；避免每行查询任务造成 N+1 |

text 接口的 limit 初始默认 1 段、最大 10 段，同时受总响应 64KiB 限制；单段过长必须拆分，不能让分页越过上限。成功正文详情最大 2MiB 来自解析总限制，前端优先使用分段接口。

示例兼容：仍可通过原 GET 详情查看正文；新分段接口如覆盖示例，用既有正文构建有限阅读段并标记无 PDF 页码，不伪造解析任务或 PDF 页码。首次实现必须选定并在 OpenAPI 说明，不让前端依赖模糊行为。

POST 开始/重试受全局写入开关及单用户待办限制约束，建议每用户未完成任务最多 10 个。超限返回 429，不允许用户不断新建任务填满队列；新上传时须在原确认事务预留该额度，超限则上传失败且交给 A1 清理，不留下“已成功但永远未排队”的半成品。

## 11. 已有数据与升级方式

- 不在 Flyway 中扫描文件或解析 PDF；V5 只做表结构与必要的安全字段兼容。
- 新上传默认同事务排队；历史 A1 上传显示“开始解析”，逐份触发，不在启动时无上限全量回填。
- 开发库先备份/迁移，保留示例和既有审核资料，记录任务及正文关联供人工观察。
- MySQL 集成测试使用隔离临时库；不能对固定开发库或生产库运行清库测试。
- 上线前备份 SQL 与文件，先确认新表、默认 worker 开关、子 JVM 产物和挂载资源。开关关闭只停止领取新任务，不能绕过租约和当前任务清理。
- 应用回滚不删除 V5 或 Flyway 历史；核实旧 A1 对新增字段/表和 TEXT 扩容兼容。关闭新 worker，再回到经过验证的旧镜像；保留待办供恢复。

## 12. 验证和审核标准

| 验证项 | 必须展示的证据 |
| --- | --- |
| 正常 PDF/TXT/MD | 上传 → 排队 → 成功 → 查看正文；PDF 页码/文本行号正确，下载原文件摘要不变 |
| 既有两份示例 | 原文和导入行为保持，无虚假原文件/任务 |
| 历史 A1 上传 | NOT_REQUESTED → 手动开始，重复开始只有一个任务 |
| 文件异常 | 无文字、混合空页、损坏、加密、错误编码和超限分别有明确结果 |
| 身份隔离 | 两账号不能读取、排队或重试对方文档；账号停用、成员失效和删除后不能发布/读取 |
| 并发/故障 | 两个领取者只有一个成功；杀掉执行器/服务后恢复；过期旧 token 不可写回 |
| 删除竞争 | 解析中删除、成功提交与删除竞争，都不能让文档重新可见 |
| 重试限制 | 自动与手动共享上限，重复点击不增加并行任务，终态不无限空转 |
| 资源约束 | 大正文、多页、超时子进程、内存及临时盘压力；失败后 API 健康、进程和临时文件可回收 |
| 事务原子性 | 上传确认与排队同成同败；正文/位置/任务成功同成同败，部分产物不提前可见 |
| 前端 | 默认展开、状态变化、正文位置、失败重试、刷新恢复、移动布局及轮询停止 |
| CI / Apifox | H2 与真实 MySQL、接口错误/鉴权/CSRF、前端检查；新增契约同步并回读验证 |

本节是验收要求，不是本轮已通过的测试。性能指标在实测后填写，不先写“高并发”“毫秒解析”等结论。

## 13. 开发顺序与审核停点

1. **A2 设计审核（当前）**：确认范围、状态、表、资源上限和对子 JVM 的取舍。本轮不执行 V5。
2. **执行器验证**：审核通过后创建 Issue 与 feat/ingestion-正文解析 分支，先验证打包、真实容器执行、超时终止和资源开销；不部署公网。
3. **解析与持久任务**：实现 V5、格式提取、位置、任务/租约、失败恢复、原子发布和权限/删除竞争。
4. **接口与页面**：接入状态、历史开始、失败重试和正文阅读，同步 Apifox。
5. **本地交付审核**：逐文件说明、数据库变化、测试/故障证据、配置与回滚；完成后停下，不自动提交、推送或上线。
6. **另行授权 PR/发布**：质量门禁通过后合并，再按用户安排部署。

代码提交采用中文 Conventional Commits，正文 Refs: #实际Issue编号；PR 独立行 Closes #实际Issue编号。一个可独立构建审核的意图一个提交，不为拆提交留下不可运行的中间状态。本计划通过不等于授权自动走完发布。
