## 1. 已确认的方向与尚未确认的选择

已确认：先文件卷交付，不必现在购买云对象存储；保留存储接口，后续加入 S3 兼容实现。先完成真实文档 RAG 闭环，再专门完成可靠上传增强，形成能演示和验证的工程能力。开发/生产共用实例但数据与账号隔离。

尚未确认：具体 Embedding/Chat 提供方与模型版本；S3 兼容存储的具体产品；后续对外账号准入方式。首轮小文件上传不依赖这些选择，不因此收集密钥或新建服务。

不把 MinIO 社区旧部署直接定为长期生产默认选项，原因及官方依据见方案第 3 节。S3 指接口能力，不要求购买 AWS 服务。

## 2. 本轮实际新增与不做的内容

下一轮 A1 只交付：已登录的独立用户向自己的现有知识库上传 PDF/TXT/Markdown，查看元数据、下载原文件和删除。现有示例库可作为目标，不先开发新建知识库/企业管理一整套页面。

不做解析、Embedding、ES、聊天、秒传、分片、文件覆盖和版本更新。上传完成显示“原文件已保存，待接入解析”，不能显示 READY 或可问答。

后续阶段：A2 解析与任务恢复 → A3 向量与检索 → A4 引用问答 → A5 对象存储与可靠上传增强。A5 是明确的项目里程碑，不是无限期搁置的可选口号；完成前不在简历宣称已支持断点续传。

## 3. A1 用户故事与界面

1. 用户进入“我的资料”，打开本人知识库，选择一份不超过 20MiB 的文件。
2. 页面显示类型/大小限制，上传时显示进度、禁止重复点击，取消仅代表停止本次请求，不承诺已撤销服务端完成的提交。
3. 成功后列表可见文件名、大小、上传时间、来源为“用户上传”、处理状态；现有示例仍可正常打开。
4. 点击下载得到与本地原文件摘要一致的内容；点击删除需一次明确确认，列表移除，旧链接不可访问。
5. 失败提示稳定错误码和 requestId，不显示真实磁盘路径或存储异常细节。

当前体验凭据可能被多人共用，共享账号不能证明用户隔离。因此生产上传默认关闭，或仅给独立验收账号开放；本轮不顺手开放公网注册。用户用独立账号审核后，再确定公开体验策略。

## 4. A1 后端职责划分

按需新增 document 模块：

- DocumentController：HTTP、multipart 参数、DTO、CSRF/鉴权边界，业务用例委托给服务。
- DocumentService：上传/下载/删除的权限与事务编排；通过现有个人区域/知识库服务取得当前归属。
- DocumentRepository：参数化 SQL 和带组织/知识库范围的查询，沿用当前 JDBC 风格，不为了命名强制改成 JPA。
- FileStorage：仅提供当前需要的写入、读取、检查、删除契约，不先造供应商管理平台。
- LocalFileStorage：实现持久化目录存储、临时写入与原子发布，流式读取和摘要计算，不把整文件读入 byte[]。
- UploadRecoveryWorker：持久化上传/删除待办的补偿与过期恢复；失败不无限重试，日志不记录正文或凭据。

不要把这些名称当作必须一比一创建的类清单；可以随实际职责合并小类型，但 Controller 不直接访问存储/拼 SQL。

## 5. A1 数据库迁移设计

新增 V4，绝不修改已发布 V1～V3。实施前再次检查迁移版本，若已有其他迁移占用 V4，顺延新版本。

当前 V3 的 documents.sample_key/seed_version、document_versions.content_text 等字段按“已有正文的示例”设计，不能直接用假 sample_key 或空正文伪装上传文件。

拟定调整：

| 对象 | 调整 | 审核重点 |
| --- | --- | --- |
| documents | 增加来源 SAMPLE/UPLOAD；上传文档允许示例字段为空，示例字段原值保持 | 用约束维护来源与字段组合；不能破坏示例唯一性 |
| document_versions | 上传版本允许尚无正文；维持内容 SHA-256 与 NOT_INDEXED 语义，正文未生成不等于解析成功 | 旧示例正文、摘要、版本查询保持兼容 |
| document_files（新增） | 文档版本关联存储 key、原文件名、大小、实际 MIME、创建人、原文件可用状态 | 组织/版本一致、随机对象 key、不可直接对外返回 key |
| document_uploads（新增） | 用户/组织/目标库、幂等键、请求特征、预留容量、状态、租约、已确认摘要、临时对象标识、错误码 | 幂等范围与并发唯一约束、重启后可恢复 |
| document_cleanup_jobs（新增或并入已有上传恢复任务） | 删除和失败残留清理的持久待办 | 不能仅靠内存线程或事务提交回调保证清理 |

A1 中每份原文件只归属一个文档版本，不做物理内容共享或引用计数。A5 再按需要迁移 file_blobs 与复用关系，避免第一轮先做复杂共享对象 GC。

小文件同库重复在服务端完整接收和验证后提示已存在，不称为秒传。并发同内容请求应串行核实目标库/上传人范围并以唯一约束兜底；已删除文档不阻止合法重新上传。

## 6. A1 接口契约草案

所有写请求需要现有 CSRF 头，接口统一返回 requestId；未知/无权资源按现有策略返回 404，不泄露存在性。新增契约在实现时生成 OpenAPI 并同步 Apifox，不在设计阶段创建空接口资源。

| 接口 | 预期行为 |
| --- | --- |
| POST /api/v1/knowledge-bases/{id}/documents | multipart 单文件，要求 Idempotency-Key；首次成功 201，安全重放返回同一资源；响应含文档 ID、元数据、来源和处理状态 |
| GET /api/v1/knowledge-bases/{id}/documents | 扩展现有列表；示例与上传文档均可见，补充来源/文件元数据，前端解析兼容 |
| GET /api/v1/documents/{id} | 现有示例正文契约不变；未解析上传文件返回明确 DOCUMENT_NOT_PARSED，不返回假正文；元数据从列表或明确新增的详情契约取得 |
| GET /api/v1/documents/{id}/download | 鉴权代理下载，Content-Disposition 为 attachment，no-store；无原文件的示例返回 ORIGINAL_FILE_UNAVAILABLE |
| DELETE /api/v1/documents/{id} | 标记逻辑删除并提交持久清理待办，返回 204；已知属于本人且已删除则幂等 204，未知或他人资源仍为 404 |

并发处理中相同幂等键返回 409 UPLOAD_IN_PROGRESS，客户端稍后使用同一键重试；同键不同请求特征返回 409 IDEMPOTENCY_CONFLICT。完整成功响应的重放还必须复查文档当前未删除/仍有权限，不能通过旧幂等结果绕过撤权。

错误提案：400 参数/文件损坏；413 超限；415 类型不支持；409 重复/幂等冲突；429 额度或频率限制；503 存储暂不可用。最终状态码与错误码以代码和 OpenAPI 一致验收。

## 7. A1 上传一致性与恢复

采用短事务 + 外部 I/O + 短事务：

1. 认证并检查目标库写权限、大小、来源开关；短事务创建幂等记录与容量预留。针对同一上传人用数据库锁串行预留，不能多个并发请求各自读取旧用量后超额。
2. 在挂载目录的暂存区流式写入，计算服务端 SHA-256，核验格式和真实长度。客户端摘要只能作辅助，不作为信任依据。
3. 在同一文件系统内将临时对象发布到不透明 key；长 I/O 不持有数据库事务。
4. 短事务复查身份/资源状态，确认去重与配额，创建逻辑文档/版本/原文件记录并完成上传状态。
5. 响应丢失时可以同幂等键恢复结果；进程在任一阶段退出，由持久化状态、租约和存储检查恢复或安排清理。

对象已落盘但数据库提交失败必须可追踪，不能只在 catch 中 try-delete 之后忘记。过期扫描要使用状态/版本/心跳条件，避免误删还在写入的请求。清理失败有有界重试及可查询错误，容量预留不能永久占用。

删除时先在事务中撤销逻辑可见性并创建清理任务，原文件失败重试不影响“下载立即被拒绝”。清理原文件前再次核实它仍属于被删除版本；不得按文件名或宽泛目录批量删除。

## 8. A1 文件安全与资源配置

拟定初始值：20MiB/文件、100MiB/个人区域总量、同时上传 2 个、日次数和暂存过期可配置。正式数值经用户审查和压测调整，不是当前线上限制。

仅支持有文本层 PDF、UTF-8 TXT、Markdown；空文件、损坏/加密 PDF、伪造 MIME 拒绝或给出清晰的后续解析限制。扫描 PDF 是否无文本在 A2 判断，不能在 A1 只凭扩展名宣称能解析。

文件名只作展示，不参与物理路径；拒绝路径穿越、NUL、换行和危险下载头。Markdown 不渲染原始 HTML；PDF 原文件走下载，不开启未经评估的内联预览。

开发与生产使用不同的存储根和挂载；容器内固定 /data/docweave，生产以原 UID 10001 可写、其他目录保持只读。数据库仍由独立环境账号访问。持久化目录必须纳入备份，原先只有 MySQL 备份并不足以恢复上传文档；数据库与文件快照的一致性和恢复检查写进运维说明。

联动调整 Nginx 请求体上限、Spring max-file-size/max-request-size、超时、容器临时目录空间及日志。HTTP 请求上限要大于 20MiB 以容纳 multipart 开销；不能只改业务常量。鉴权失败、上传中断及超限均应清理暂存且保持服务可用。

## 9. A1 测试与审核停点

必须提供真实 MySQL + 真实文件目录的集成验证，不只 Mock 存储成功。自动化测试使用隔离临时库/临时目录，不能清空共享开发或生产库。

- 正常上传→列表→下载，字节长度和 SHA-256 一致；现有示例预览/入库回归通过。
- 两个独立账号：他人知识库上传、他人下载/删除均被拒绝，不能从摘要或错误获知其他组织文件。
- 同键重试、响应丢失、同内容并发、同键不同内容分别符合契约；不重复创建或错误复用。
- 超限、错误 MIME、危险文件名、空文件、存储权限错误均有明确结果，不泄露真实路径。
- 预留后失败、文件落盘后 DB 失败、确认后响应失败等故障注入；重启后恢复/清理正确。
- 删除立即不可下载，清理失败后可恢复；保留的示例不因上传/删除受到破坏。
- 前端真实浏览器验证上传、失败提示、下载、确认删除和移动布局；接口带 requestId。

交付时必须有：逐文件审核 MD、迁移前后表对照、接口和 Apifox 回读、实际验证结果、限制、部署与回滚说明。完成后停在本地供用户审核，不自动 commit/push/PR/部署，除非当轮再授权。
